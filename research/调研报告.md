## 1. 执行摘要：最重要的 5 条发现

1. **不要在本规模上做线性注意力/SSM。** HuggingFace 的系统对比（arXiv:2608.28444）结论明确：「训练预算有限时，改用 SWA 是比 retrofit 线性注意力更有效的降推理显存手段」，且 NIAH/BABILong 上 SWA 比线性注意力高 2–10 倍。唯一的 <500M 正例（arXiv:2609.29618）是**单种子、参数量不匹配、作者自己声明不支持一般性结论**的探索性实验。

2. **16K 词表对本项目偏小，但方向是对的；PanGu-π 的 48K/97.86% 数字无法核实。** 已发表的系统研究（arXiv:2608.11361）给出明确部署结论：**B=1 的端侧部署应当使用 V≈32K**，而 1.3–2.3B 规模的质量最优点在 V≈65K。该文同时报告词表在最优区间内质量差异 <2% BPB，说明词表主要是系统参数。PanGu-π 相关数字在 arXiv 上检索不到可核实来源。

3. **SWA:GA 均匀交错很可能不是最优，且这是本次调研中投入产出比最高的一个消融。** ConSA（arXiv:2606.18056，0.6B/1.7B 实测）发现学习到的 FA/SWA 分配把 SWA 放在底层、FA 集中于**连续的中间层块**，明确「偏离了规则式方法的均匀交错模式」；BOSCH（arXiv:2604.05942，ACL 2026，1.7B–30B）发现**逐层自适应 SWA 比例优于层间启发式**。两者独立指向同一结论，且方向与当前实现相反。

4. **合成数据的正确用法是「改写真实语料」而非「凭空生成」，且在数亿 token 预算下不要指望复现 5–10× 加速。** Kang et al.（EMNLP 2025，>1000 个 LLM、>10 万 GPU 小时）确认：1/3 改写 + 2/3 真实可加速 **5–10×**——但原文限定在「较大数据预算」；而纯生成的教科书式数据在**小数据预算下**损失显著更差。这与 2025 工作组给的前提一致，但补上了前提缺失的边界。

5. **除 Muon 外，本规模上有真实证据的优化器改动很少，但有两个「近乎免费」的选项**：GradPower（arXiv:2505.24275，ICML 2026，**66M–2B 实测**，一行代码改动，在 cosine 与 WSD 下均降低终局 loss）与 μP 超参迁移（arXiv:2511.19496：**20M 代理模型调的超参可直接迁移到 1.3B，且在 tie-word-embedding 架构下成立**——与本项目的 tied embedding 完全对应）。另外 WSD 的出处已确认为 MiniCPM（arXiv:2404.06395，Hu et al. 2024）。

## 2. 六项逐条调研

### 2.1 状态空间/混合架构在 100M–350M 的现状

#### 2.1.1 结论：纯线性/递推注意力在此规模无可靠证据支持

| 证据 | 规模 | 关键数字 | 性质 |
|---|---|---|---|
| arXiv:2608.28444「Sliding-window beats linear attention」<br>Jolicoeur-Martineau 等（HuggingFace），v2 2026-10-04 | 多个 LLM + 下游任务 | NIAH/BABILong 上 SWA 比线性注意力高 **2–10 倍**；原文结论：「当训练预算有限时，改用 SWA 是比 retrofit 线性注意力更有效的降低推理显存成本的手段」；线性注意力「需从头训练或大规模 retrofit 才能获益」 | 系统对比 |
| arXiv:2402.18668 BASED（Arora 等） | **至 1.3B** | 线性 + SWA 混合，困惑度追平最强次二次模型（Mamba），召回密集任务上**领先 6.22 个准确率点**；1.3B 生成 1024 token 时吞吐比 FlashAttention-2 高 **24×** | 正例，但 ≥1.3B |
| arXiv:2405.21060 Mamba-2（Dao & Gu, ICML 2024） | 小到中等规模 | 「SSM 如 Mamba 已在小到中等规模上匹配或超过 Transformer」；Mamba-2 比 Mamba 快 2–8× | 奠基性声称，未给 <500M 的独立复现 |
| arXiv:2609.29618「Small MLA–SSM Hybrid 消融」 | **117–217M 激活参数** | MLA-only PPL **315**；SSM-only PPL **239**；dense-FFN hybrid **231**；top-2 ternary-MoE hybrid **240** | ⚠️ **单种子、参数量未配平、评估流可能与训练源重叠**；作者原话：「这些结果支持实现层面的假设，而非关于 MLA、SSM 或 MoE 的一般性结论」 |
| arXiv:2511.05560 BLaLM（BabyLM 2025 workshop） | STRICT-SMALL（BabyLM 约束下的最小规模） | 线性注意力 + SWA「持续改善 zero-shot 表现」；同文报告 **Muon 在此规模优于 AdamW** | 小规模正例，但为共享任务受限量 |

**判读**：唯一在 <500M 有直接对照数据的结构化研究（arXiv:2609.29618）**明确声明不支持一般性结论**，且其数字方向甚至与 BASED 相反（该文中 SSM-only 反而优于 MLA-only）。同时 arXiv:2608.28444 从训练预算受限的角度给出否定结论。综合判断：**本项目规模下没有足够证据支持切换到 SSM/线性注意力。**

#### 2.1.2 能否导出到 llama.cpp —— 可以，但只能作为「已命名架构」

我直接读取了 llama.cpp 主干 `src/llama-arch.cpp`（2026-10-11 抓取）：

**递归/纯 SSM 架构**（`llm_arch_is_recurrent` 返回 true）：
```
mamba, mamba2, rwkv6, rwkv6qwen2, rwkv7, arwkv7
```

**混合架构**（`llm_arch_is_hybrid` 返回 true）：
```
jamba, falcon-h1, plamo2, granite_hybrid, lfm2, lfm2moe,
nemotron_h, nemotron_h_moe, qwen3next, kimi_linear,
bailingmoe3, kimi_k3, glm5-next, qwen35, qwen35moe,
qwen4exp, deepseek4, minimax_01
```

**关键结论**：
- 导出的**可行路径存在但很窄**——只能伪装成一个已存在的命名架构（如 `qwen3next` 或 `mamba2`），需要逐个张量对齐该架构的硬编码布局。**不存在**「导出成受支持的近似架构」的通用变通：GGUF 的张量命名与架构名强绑定。
- 相关 GGUF KV 键确实存在：`%s.ssm.conv_kernel`、`%s.ssm.state_size`、`%s.ssm.time_step_rank`、`%s.attention.recurrent_layers`、`%s.full_attention_interval`。
- 对本项目的实际含义：**现有 SWA 架构走 `qwen3` 路径导出是安全的**（已有 `qwen3.swa_nums` 约定），而任何自定义线性注意力都无法低成本导出。**这本身就是一条不采用 SSM 的独立工程理由。**

#### 2.1.3 「纯注意力 vs 线性/递推 vs 混合」的系统对照是否存在

**部分存在，但无一在 <500M 上给出可复现的对照**。最接近的是 arXiv:2608.28444（对比 SWA vs retrofit 线性注意力，但基线是现成 LLM 而非从头训练）与中国团队的 arXiv:2606.15378（见 §2.2.3）。

### 2.2 注意力机制的边际收益

#### 2.2.1 SWA:GA 比例是否被系统研究过

| 证据 | 规模 | 结论 |
|---|---|---|
| **arXiv:2606.18056 ConSA** | **0.6B 与 1.7B** | 用 L0 正则学习 FA/SWA 的二值分配。**学习到的分配一致优于规则式基线**；KV-head 粒度明显优于 layer 粒度；学到的模式是「**SWA 放在底层，FA 集中于连续的中间层块**，偏离均匀交错」；该结构在跨模型规模、稀疏度、分配粒度上**持续存在** |
| **arXiv:2604.05942 BOSCH**（ACL 2026 Main） | 1.7B–30B，4 种 SWA 比例 | 「自适应逐层 SWA 比例分配」优于层级启发式与 6 种强静态 head 级方法；**SWA 比例越高增益越大**；分析发现不同 SWA 比例下选中的 head 存在大量 turnover |
| arXiv:2605.31268 Mellum2 | 12B MoE / 2.5B 激活 | 采用 **SWA 3/4 层**（即 3:1，**比本项目的 6:1 更激进地使用 SWA**），称「每个选择都经消融验证」 |
| arXiv:2601.02780 MiMo-V2-Flash | 309B / 15B 激活，27T token | 5:1 混合比例、128 窗口（本项目设计来源） |

**直接回答「5:1 / 3:1 / 7:1 哪个好」**：**未找到公开数据**。没有任何论文在 <500M 上系统对比过这三种比例。现有证据只能说明：比例很重要、逐层自适应优于均匀交错、且比例越高（更多 SWA）时自适应分配的收益越大。**这是一个明确的空白，也因此是一个高价值、低风险的消融位。**

#### 2.2.2 「小模型应全部用全局注意力」——正例与反例都存在

**反例（支持保留 SWA）**：
- arXiv:2608.28444：SWA + attention sink 在长上下文与生成任务上优于多数 retrofit 线性注意力模型，且「无需额外训练、极快、显存占用小」
- arXiv:2606.02680 Post-Boundary Bridge（**205M–2.07B**，本项目规模覆盖）：混合架构「保持接近 Full 的困惑度」，且 **205M 时 PBB 与 SWA 混合的困惑度持平、源检索准确率更高**
- arXiv:2608.25096：GQA + SWA 在解码能耗上「维持几乎恒定的能耗」，而 MHA 模型能耗随上下文陡增

**正例（支持全注意力或更少 SWA）**：
- arXiv:2606.15378：「长程检索主要由全注意力层承担，而高效注意力塑造其优化轨迹」；并给出反直觉现象 **Large-Window Laziness**——更大的 SWA 窗口反而**延迟**全注意力层中检索头的形成
- arXiv:2610.10114「Mechanics of Long-Context Hybrid Models Part 1.1」：SWA 混合模型存在 **Short-Context Learning Trap、Short-Window Weariness、Long-Window Laziness** 三个问题，且「需要更长的窗口才能在长上下文持续预训练中提升表现」
- arXiv:2512.10411 SWAA：SWA 施加于「每个模块、每个时刻」会导致长上下文性能灾难性崩塌

**对本项目的直接推论**：训练上下文 512、窗口 128、全局层仅 2 层，正处在上述「短上下文学习陷阱」的描述区间内。**这是本次调研中风险最高的一条。**

#### 2.2.3 滑动窗口大小的经验规律（64/128/256/512）

**未找到在 <500M 上直接对比 64/128/256/512 的公开数据。** 可用的间接约束：
- arXiv:2610.10114：SWA 混合需要**扩展窗口**才能在长上下文持续预训练中获得提升
- arXiv:2606.15378：**更大的窗口会延迟检索头形成**（Large-Window Laziness）
- arXiv:2602.09862 Blurry Window Attention：BLA 在 MQAR 上状态效率是 SWA 的 **8×**，且在 RegBench 上只有 BLA 与 SWA 随状态增大而改善
- 本项目实际有效窗口 128、上下文 512 → 窗口仅覆盖序列的 25%

#### 2.2.4 MLA 在小模型上的效果

**结论：在小模型上 MLA 不划算，且证据强度弱。**

- arXiv:2609.29618（117–217M）：MLA-only PPL 315，**劣于** SSM-only（239）与 dense-FFN hybrid（231）；原文还提到 MLA-only 的 TTFT 曲线「最平坦，但 dense Transformer 绝对速度快得多」
- arXiv:2603.30033 Tucker Attention：Tucker 相比 GQA 与 MLA **少一个数量级的参数却达到可比的验证指标**，并指出 MLA 可被进一步简化
- arXiv:2502.14837 MHA2MLA（ACL 2025）：MHA→MLA 的迁移需要 **0.3%–0.6% 数据**才能恢复性能，说明两者高度可互换——参数量收益在微调场景下被抹平
- arXiv:2509.16686 EG-MLA：声称相对 MHA 减少 91.6% KV，但实验规模「成功扩展到 1B 以上」

**适用边界**：MLA 的收益本质是 **KV Cache 压缩**。本项目上下文 512、窗口 128、GQA 12头/4KV头，KV Cache 本来就已很小，**MLA 的目标问题在此不存在**。

### 2.3 MTP / 多 token 预测

#### 2.3.1 MTP 深度 1/2/3 的对照数据

**原始论文**：arXiv:2404.19737（Gloeckle 等，Meta）——在共享主干上使用 **n 个独立输出头**预测后 n 个 token。关键表述：「**该方法对更大的模型规模越来越有用**」。4-token 预测模型在大 batch 下推理快至多 **3×**。给出 13B 的 HumanEval +12%、MBPP +17%。

**深度的直接对照数字：未找到公开表格化数据。** 原始论文未以「深度 1 vs 2 vs 3 的 loss 曲线对照」形式呈现，MiMo-V2-Flash 的 3 层 MTP 也没有公布深度消融表。

**在小模型上的反向证据（这是最关键的一条）**：
> arXiv:2505.22757「Pre-Training Curriculum for Multi-Token Prediction」（Aynetdinov & Akbik，**ACL 2025 Main**）原文：
> **「prior work has shown that smaller language models (SLMs) struggle with the MTP objective.」**
> 该文提出正向课程（NTP → MTP 渐进）让 SLM 更好地利用 MTP 目标，**同时保留自投机解码收益**；反向课程 NTP 性能更强但**完全丧失投机解码收益**。

#### 2.3.2 训练期 MTP 收益能否在推理期兑现

- **正例**：arXiv:2601.02780 MiMo-V2-Flash——3 层 MTP 实现 **3.6 接受长度、2.6× 解码加速**（309B/15B 激活，27T token）
- **正例（单头）**：arXiv:2605.31268 Mellum2——采用**单个** MTP 头同时作为预训练辅助目标与投机解码 draft 模型
- **反证/条件**：arXiv:2607.08690「Practical Investigation of Training-free Relaxed Speculative Decoding」——「许多 relaxed 方法依赖一个**本身就是好的语言模型**的 drafter，因而**不适合轻量的专用 MTP drafter**」。这对 108M 规模的 MTP 头是直接的风险提示
- **反证（课程视角）**：arXiv:2505.22757 的反向课程**丧失全部投机解码收益**——说明 MTP 的推理期收益与训练期 NTP 性能存在**直接的此消彼长**，不是免费的

#### 2.3.3 Medusa / EAGLE 系列在小模型上的结论

- arXiv:2401.10774 Medusa：Medusa-1（冻结主干、仅训 head）**>2.2× 无损加速**；Medusa-2（联合微调）2.3–3.6×。论文评估「多种尺寸的模型」，但**未给出 <1B 的分档结论**
- arXiv:2610.07659 DLoop：跨 EAGLE-3、DFlash、Domino、DSpark、MTP 模块，墙钟加速提升 5–41%
- arXiv:2602.03769「Reasoning with Latent Tokens」：向自回归模型引入**辅助 MTP 目标**可在传统上困难的推理任务上带来实质提升
- arXiv:2602.06019「Multi-Token Prediction via Self-Distillation」：**GSM8K 掉点 <5% 的前提下解码快 3×+**，且**最终模型保持与原 checkpoint 完全相同的实现**，无需额外推理代码

**综合判读**：MTP 在 100M–350M 上是**未验证的赌注**。原始论文明说「对更大模型越来越有用」，ACL 2025 的论文明说 SLM「难以利用 MTP 目标」。本项目已实现 depth=1，这是**正确的保守选择**。

### 2.4 数据配比与合成数据

#### 2.4.1 「30% 合成 + 70% 真实」的出处与实验条件

**出处已确认**：**Kang et al., arXiv:2510.01631「Demystifying Synthetic Data in LLM Pre-training: A Systematic Study of Scaling Laws, Benefits, and Pitfalls」**，**EMNLP 2025 Main**。

**实验条件（原文摘要明确给出）**：
- 规模：**>1000 个 LLM，>100,000 GPU 小时**，统一协议 + 标度定律
- 合成数据分两类：**rephrased（改写真实语料）** 与 **generated textbooks（凭空生成教科书）**
- 原文关键论断：
  1. 纯改写合成数据预训练**并不比**真实网页文本快
  2. **1/3 改写合成 + 2/3 真实网页文本**，在**较大数据预算**下可加速 **5–10×** 达到同一验证损失
  3. 纯教科书式生成数据在**许多下游领域损失显著更高，尤其在小数据预算下**
  4. 「好」比例**依赖模型规模与数据预算**，改写类**经验收敛到约 30%**
  5. 更大的生成器模型**不必然**产生优于 ~8B 参数模型的预训练数据

**独立复现情况**：该论文规模空前（>10 万 GPU 小时），但**未找到针对其 30% 结论的独立第三方复现**。应标注为「论文声称，尚未见独立复现」。

**对本项目的直接含义（关键）**：本项目预训练预算为数亿 token，处于该论文中「收益最弱」的一端——原文明确把「加速 5–10×」限定在**较大数据预算**，并明确指出小预算下**纯生成数据更差**。30% 这个数字**不是**可以在本项目直接照搬的普适常数。

#### 2.4.2 「改写真实语料优于凭空生成」的具体证据

同一篇 arXiv:2510.01631 即为核心对照：rephrased 类 vs textbook-generated 类，在纯用与混合两种设定下，前者全面更优。且其对模型崩溃的结论分型清晰：
- **改写类合成：n=1 单轮大规模训练下，在可预见的规模内无性能退化**
- **教科书式纯生成的混合：呈现「模型崩溃」理论预测的模式**

补充证据 arXiv:2412.14689（ICML 2025，「How to Synthesize Text Data without Model Collapse?」）：预训练实验揭示**合成数据比例与模型性能呈负相关**；提出的解法是**在人类数据上做 token 级编辑**得到「半合成」数据，并给出理论证明：token 级编辑可防止模型崩溃，测试误差有有限上界。

#### 2.4.3 合成数据收益在多大规模以下失效

**这是本次调研中你特别标记的问题，直接回答：**

- arXiv:2510.01631 的分型已经给出答案：**失效的不是「模型大小」而是「数据预算」**。原文的负面结论（小预算下更差）针对的是 **textbook-style 纯生成**数据，而对 **rephrased 改写**数据，在「可预见的规模内」未观察到退化。
- 因此在本项目的数亿 token 预算下：
  - **改写类合成数据**：风险低，值得做
  - **凭空生成的教科书类数据**：**明确不应做**，原文点名「尤其在小数据预算下」更差
- 另一条规模边界：arXiv:2503.19551 SynthLLM（COLM 2025）发现合成数据带来的性能提升**在约 300B token 处趋于平台**——本项目离该拐点有两个数量级之远，任何「靠合成数据追平更大模型」的预期都不成立。

#### 2.4.4 难样本重采样（按 loss 加权重采样）在 100M–350M 的验证

**找到的最相关证据**：arXiv:2407.01492 **RegMix**（ICLR 2025）——这是本项目**完全可复现**的代理实验范式：
- 训练 **512 个 1M 参数模型、每个 1B token**，用回归拟合来预测未见混合的性能
- 用该方法预测出的混合训练 1B 模型 / 25B token（**大 1000 倍、长 25 倍**），在 64 个候选混合中表现最佳
- **使用仅 10% 的算力即匹配或超过 DoReMi**
- 关键发现：**网页语料而非「感知上高质量」的 Wikipedia，与下游性能的相关性最强**；领域间交互复杂且常与常识相悖，因此需要自动方法；**数据混合效应超越标度定律**

**未找到**在 100M–350M 上直接验证「按 loss 加权重采样」的论文。RegMix 的 1M 代理规模虽更小，但方法学可直接移植。

### 2.5 优化器与调度

#### 2.5.1 WSD 的原始出处 —— 已确认

**原始出处：MiniCPM 论文 arXiv:2404.06395（Hu et al., 2024），原文：**
> 「For data scaling, **we introduce a Warmup-Stable-Decay (WSD) learning rate scheduler (LRS)**, conducive to continuous training and domain adaptation.」

佐证：arXiv:2503.12811 在描述 WSD 时明确引用为 **「Hu et al, 2024」**。

**实践证据**：

| 证据 | 规模 | 结论 |
|---|---|---|
| arXiv:2410.05192「Understanding WSD: A River Valley Loss Landscape Perspective」（Wen 等） | **0.1B–1.2B** | 提出 WSD-S，**在单次运行中跨多个算力预算获取多个 checkpoint 时优于 WSD 与 Cyclic-Cosine** |
| arXiv:2508.01483（TMLR 2025） | — | cooldown 阶段形状存在**偏差-方差权衡**；平衡探索与利用的形状一致更优；**在 cooldown 阶段提高 β₂ 有持续改进** |
| arXiv:2503.12811 Multi-Power Law | 多种规模 | 自动发现的调度形状类似 WSD 但**终局 loss 略低** |
| arXiv:2608.28308 OpenEuroLLM 标度定律 | 稠密 LLM | 系统研究 WSD 下 LR/批量的最优值边际演化；**最优 LR 与 batch size 在 stable 阶段与 decay 阶段之间可迁移**；全部预训练运行开源 |
| arXiv:2509.19189（NeurIPS 2025 Spotlight） | **0.1B–1.1B** | 推导并验证：**(i) 更高容量模型对数据与算力更高效；(ii) 学习率衰减提升训练效率；(iii) WSD 型调度优于纯衰减** |
| arXiv:2601.09000 | Pythia-like + CIFAR10 CNN | WSD 的有效性**不是 Transformer 特有**，在 CNN 上观察到定性一致的信号 |

**替代方案**：arXiv:2507.17634 **WSM**（无衰减调度，通过 checkpoint 合并）报告全面优于 WSD：MATH **+3.5%**、HumanEval **+2.9%**、MMLU-Pro **+5.5%**，且 merge duration 是最关键因素。arXiv:2507.09846（Schedule-Free，NeurIPS 2025）则论证 SF-AdamW 可隐式做权重平均而**无需衰减阶段或额外显存**。

#### 2.5.3 小模型 batch size 与学习率关系的可迁移定量结论

- arXiv:2610.08975「**The Best Optimizer Depends on Batch Size**」（Dang、Wen、Malladi，2026-10-06）——两条硬结论：
  1. **不存在对 Muon 一致有效的缩放规则**
  2. **经过充分超参调优后，语言模型预训练的最佳优化器仍随 batch size 改变**
- arXiv:2609.08690「Hyperparameter Scaling Laws Across MoE Sparsity」（1,800 次预训练、~20T token、20 万 H800 等效小时）：固定稀疏度下**最优 batch size 随训练 token 数 D 呈幂律**，**最优学习率随训练算力 C 缩放且对模型/数据分配稳健**
- arXiv:2609.37745：最优学习率是**优化器相关**的——SGD 下与 D 无关，Adam 下随 D 下降；但**调优到最优后，各优化器的 loss 都回到 D^(-1/3)**。含义：**优化器只改变达到同等 loss 所需的时间常数，不改变样本效率的渐近斜率**
- arXiv:2609.35029：浅层线性网络中证明，训练时域随宽度增长时快速 LR 迁移在 **T = o(√n)** 时成立，并给出有限宽度扰动下的迁移速率刻画

**适用边界警告**：以上多数在 MoE 或大宽度下建立。本项目 `micro_bs=8, accum=4, seq=512` 的有效 batch 仅 **16,416 token/step**，属于**极小 batch** 区间，而 arXiv:2610.08975 恰恰说明小 batch 下最优优化器可能完全不同。

#### 2.5.4 「免费午餐」技巧（特殊初始化、残差缩放、depth-wise scaling）

**已实现的部分**：`model.py:303-305` 对 `o_proj` 与 `down_proj` 使用 `std = 0.02/sqrt(2*n_layer)` 的残差分支缩放初始化。这是 GPT-2 时代的主流做法。

**相关证据**：
- arXiv:2609.08574「Do New Attention Mechanisms Actually Fix Attention Sinks at Million-Token Context?」：**「训练目标产生 sink，而非架构」**，在其规模下 gating 未能复现已发表效果
- arXiv:2609.00746（EMNLP 2026）：报告**后训练注入 QK-RMSNorm 无法复现原生 QK-RMSNorm 的保护作用**——与「事后打补丁免费午餐」相反的证据
- arXiv:2605.20155 Pangu Light：权重**重新初始化**（CLAP、SLNP）在剪枝后确有增益，但属剪枝场景

**未找到**在 <500M 上验证「depth-wise scaling / 残差缩放初始化带来可测量增益」的公开对照数据。**未验证 → 是机会，但需自行消融。**

#### 2.6.2 已发表的系统性词表研究 —— 直接给出本项目的答案

**arXiv:2608.11361「Lifecycle-Optimal Tokenization: Vocabulary Size as a Deployment-Regime-Dependent Infrastructure Parameter」（2026-08-11）** 是本次调研找到的唯一系统性研究，直接对应本项目场景：

形式化总部署成本 `C_lifecycle(V) = C_train(V) + λ·C_infer(V, B)`，其中 λ 是推理量、B 是服务批量。在 A10G 与 A100 两代 GPU 上做受控实验：

1. **推理最优词表随服务批量偏移 16×**：从 **B=1 时的 32K** 到 **B≥64 时的 524K**，驱动因素是 `V×d` unembedding 矩阵读取的摊销
2. 在 **1.3–2.3B 模型规模**，质量（bits per byte, BPB）在 **V=65K** 处最优，证实词表偏好**依赖模型规模**
3. 生命周期最优词表与训练最优词表在生产部署中**最多相差 16×**
4. **质量在最优区间内近似不变（<2% BPB 跨度）**——词表是纯系统优化，在测量区间内无质量代价
5. **明确部署建议：端侧部署（B=1）应使用 V≈32K；数据中心服务（B≥64, λ≥10）应使用 V≈131–262K**

**对本项目的直接推论**：
- 本项目是 **B=1 的端侧单卡部署**（llama.cpp 本机推理）→ 该文的建议是 **V≈32K**
- 当前 **16K 低于该建议值一个档位**
- embedding 参数占比：**16384 × 768 = 12.58M / 108.16M = 11.6%**（与项目文档的 11.7% 一致）
  - 提升到 32K：embedding 变为 25.17M，占比约 **23.3%**（注意：总参数量也会随之增至约 120.7M，故非 embedding 参数仍为 108.16M）
  - 但注意：结合 arXiv:2608.11361 的「质量在最优区间内近似不变」，**扩大词表的主要动机是推理速度（序列更短）而非质量**

**补充证据**：
- arXiv:2606.28057 **MultiHashFormer**（EMNLP 2026）在 **100M / 1B / 3B** 评估，用哈希签名让**多语言词表扩张保持恒定参数占用**且无需修改架构，在多基准上持续优于标准 Transformer LM
- arXiv:2610.01127 CNF-MCE：词表利用率可从 **52.9% 提升到 96.9%**（1M 词表实验）——低词表通常伴随低利用率
- arXiv:2605.22705 ToaST：⚠️ 作者在 comment 中**主动声明**其所有基线 tokenizer 因 HuggingFace `tokenizers` 库的 i32 溢出 bug（训练数据 >~108GB）训练错误，**所有对 ToaST 的比较均无效**（https://github.com/huggingface/tokenizers/issues/2058）。这条对任何引用其对比数字的工作都是警告

**未找到**：在 100M–350M decoder-only 中文模型上直接扫描 8K/16K/32K/64K 词表的公开消融。**这是一个明确的空白。**

## 4. 候选改进点清单（按预期收益 / 实现成本 / 可验证性排序）

### 评分口径
- **收益**：预期训练/推理 loss 或质量的改善幅度（1–5）
- **成本**：实现改动量（1–5，越低越好）
- **可验证性**：能否在本机有限 GPU 小时内得到有统计意义的结论（1–5）
- **GPU 小时基准**：108M 模型、seq 512、14,000 tok/s（独占）/ 11,000 tok/s（共享）
  - 50M token ≈ 1.0 h / 1.3 h ｜ 100M ≈ 2.0 h / 2.5 h ｜ 150M ≈ 3.0 h / 3.8 h ｜ 300M ≈ 6.0 h / 7.6 h
